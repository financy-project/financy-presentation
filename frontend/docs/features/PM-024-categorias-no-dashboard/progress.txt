## Rebase onto main (post PM-023 merge) — 2026-09-05

Sibling feature PM-023 ("Transações Recentes no Dashboard") merged into `main` while this stack was in flight, touching the exact same files (`queries.ts`, `use-get-dashboard.ts`, `dashboard-categories-card.tsx` placeholder, `dashboard-highlights.tsx`, `dashboard-page.tsx`) and establishing conventions this stack didn't originally follow. Rebased `PM-024/categorias-no-dashboard` → `phase-1` → `phase-2` → `phase-3` onto `main`, adapting instead of just resolving textually:

- **Architecture change adopted from PM-023**: dashboard highlight cards now call `useGetDashboard()` themselves (see `RecentTransactionsCard`) instead of receiving data via props from `DashboardPage`/`DashboardHighlights`. Dropped `DashboardCategoriesCardProps` and `DashboardHighlightsProps` entirely — `DashboardCategoriesCard` and `DashboardHighlights` are prop-less again, matching main. `dashboard-page.tsx`/`dashboard-highlights.tsx` ended up byte-identical to main (phase 2's commit no longer touches them).
- **Reused PM-023's new shared primitives** instead of the phase-2 gap-fills that predated them: `DashboardCardHeader` (`src/modules/dashboard/components/dashboard-card-header.tsx`) replaces the hand-rolled header/"Gerenciar" link markup; `resolveCategoryColorName` (`src/lib/category-visuals.ts`) replaces the module-local `COLOR_OPTIONS`/`resolveTagColor` duplicate. Also dropped the border-bottom divider under the header and switched the outer `Card` back to uniform `p-6` (no divider) to match `RecentTransactionsCard`'s established structure — a deliberate consistency choice over the divider `/figma-fidelity` had found on the Categorias frame specifically.
- All test files were rewritten to mock `useGetDashboard()` directly (mirroring `recent-transactions-card.test.tsx`'s pattern) instead of passing props.
- `use-get-dashboard.ts`/`queries.ts`/their tests merged to carry both `recentTransactions` (PM-023) and `categories` (PM-024) side by side.
- Fixed a knock-on type error surfaced by widening `UseGetDashboardResult`: `recent-transactions-card.test.tsx`, `dashboard-highlights.test.tsx` and `dashboard-page.test.tsx` (all PM-023 files this stack never otherwise touches) needed `categories: []` added to their `useGetDashboardMock.mockReturnValue` calls to keep `tsc -b` clean — folded into Phase 1's commit (via amend) since that's the commit that widens the type, so Phase 1 alone type-checks on its own.
- Verified after every phase's rebase: `pnpm test` (311/311, one pre-existing unrelated flaky timeout in `use-create-transaction.test.ts` seen once, not reproducible in isolation), `pnpm build`, `pnpm lint` — all clean on the final `phase-3-polish` tip.
